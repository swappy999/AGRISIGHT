# AgriSight — FINAL CRISP UI + MOBILE-READY PHASED PLAN

## Mission

Do not implement everything at once.

Work **ONE PHASE AT A TIME**:

```text
Implement
→ Test
→ Fix
→ Report
→ STOP
→ Wait for explicit approval
```

**Edge AI and IoT sensors are postponed until the very end.**

The current problem is information overload: scan results and AI responses show too much at once. The new principle is:

> **Show the gist first. Let the farmer choose the detail.**

---

# 1. SCAN RESULT EXPERIENCE

After a scan, do NOT dump all information onto one screen.

Show only:

```text
🌿 Tomato

⚠ Possible Early Blight
Risk: Medium

Needs attention.

[ Disease ]
[ Nutrition ]
[ Water ]
[ Prevention ]
[ Compare ]
```

Only show buttons for categories that actually have useful information.

Each button opens a dedicated detail page, panel, or bottom sheet.

---

# 2. DISEASE BUTTON

When the farmer taps **Disease**:

```text
DISEASE

Possible Early Blight
Risk: Medium

Why:
• Brown lesions visible
• Yellowing around affected area

What to do:
• Inspect nearby leaves
• Remove severely affected leaves
• Follow appropriate IPM guidance

[ Back ]
[ Ask AgriSight ]
```

Keep it short and actionable.

---

# 3. NUTRITION BUTTON

When the farmer taps **Nutrition**:

```text
NUTRITION

Possible nutrient issue:
Nitrogen

What to do:
• Check soil condition
• Confirm with soil testing
• Follow appropriate fertilizer guidance

[ Compare ]
[ Back ]
```

Never make image-only nutrient screening sound definitive.

Use wording such as **Possible Nitrogen Deficiency** when appropriate.

---

# 4. WATER BUTTON

Show only useful information:

```text
WATER

Water-stress risk:
Medium

Today's guidance:
Irrigation may be needed.

Best window:
Early morning

Why:
Low rainfall probability
High temperature
```

Do not show fake sensor values when no sensor exists.

---

# 5. PREVENTION / IPM BUTTON

```text
PREVENTION

Priority:
Monitor nearby plants

Actions:
• Inspect surrounding leaves
• Improve airflow
• Remove severely affected material
• Follow appropriate IPM guidance

[ Back ]
```

No long paragraphs.

---

# 6. COMPARE FEATURE

Provide:

```text
[ Compare ]
```

Allow the farmer to select previous scans for the same field/crop.

Example:

```text
COMPARE SCANS

Current
Aug 27
Risk: Medium

Previous
Aug 24
Risk: High

Change
↓ Disease Risk

Health
76 → 84
```

Use:

```text
↑ Increased
↓ Reduced
→ No major change
```

Show only meaningful differences.

---

# 7. AI ASSISTANT — CRISP RESPONSES

The assistant must stop producing large blocks of unnecessary content.

Default answer should be approximately:

```text
🌿 Possible early blight.

Risk: Medium

Today:
• Inspect nearby leaves
• Remove badly affected leaves
• Monitor tomorrow

[ More Details ]
```

The normal response should be short.

Only provide longer explanations when the user asks or taps **More Details**.

---

# 8. AI RESPONSE FORMAT

Default order:

```text
What's happening?
↓
Risk
↓
What to do
```

Avoid:

- long introductions
- repeated explanations
- unnecessary disclaimers
- technical model details
- repeated crop information
- duplicate recommendations

---

# 9. AI DETAIL CONTROLS

Useful optional buttons:

```text
[ Why? ]
[ What should I do? ]
[ Prevention ]
[ Compare ]
```

The UI should progressively disclose detail instead of showing everything immediately.

---

# 10. MOBILE AI ASSISTANT

Keep the assistant compact:

```text
🤖 Ask AgriSight
```

When opened:

```text
Ask AgriSight

How can I help?

🎤 Speak
⌨ Type

[ What should I do today? ]
[ Explain this scan ]
```

Do not show a giant empty chat interface before the user asks something.

The assistant must not cover:

- Scan controls
- Navigation
- Camera
- Alerts
- Important content

---

# 11. HOME PAGE

Keep Home minimal.

Home should contain only:

```text
Greeting
↓
Weather
↓
Scan Crop
↓
Important Alert
↓
Ask AgriSight
```

Optional:

```text
Tiny real health summary
```

Do NOT put detailed:

- field data
- heatmaps
- scan history
- analytics
- charts
- crop tables
- recommendations
- field management

on Home.

Those belong in the sidebar/pages.

---

# 12. INFORMATION ARCHITECTURE

Use:

```text
HOME
CROPS
FIELDS
SCAN
ALERTS
ANALYSIS
AI ASSISTANT
SETTINGS
```

### Crops
Crop management, stages, health, nutrition, history.

### Fields
Field details, images, health, heatmap, risks, scans, recommendations.

### Scan
Camera, upload, diagnosis, result details.

### Alerts
Full alerts and actions.

### Analysis
History, trends, charts, comparisons, detailed statistics.

### AI Assistant
Full AI conversation, voice, multilingual assistance.

Home remains the quick command center.

---

# 13. CARD RULE

One card = one idea.

Good:

```text
Weather
28°C
```

Good:

```text
Disease Risk
Medium
```

Bad:

```text
One giant card containing:
weather + disease + nutrition + water +
charts + history + multiple buttons
```

Break complex information into buttons or dedicated sections.

---

# 14. PROGRESSIVE DISCLOSURE

Default:

```text
Disease Risk: Medium

[ Why? ]
```

Expanded:

```text
Humidity high
Previous symptoms detected
Crop is flowering
```

Do not show all details initially.

---

Use simple wording.

Prefer:

```text
Check your crop
```

not:

```text
Initiate crop diagnostic assessment
```

Prefer:

```text
Water may be needed
```

not:

```text
Irrigation requirement detected
```

Prefer:

```text
Disease risk is rising
```

not:

```text
Elevated pathogen probability identified
```

Keep technical terminology on advanced screens.

---

# 16. LIVELY BUT SIMPLE

"Lively" means subtle interaction, not clutter.

Use:

- short transitions
- button feedback
- active states
- smooth navigation
- simple scan progress
- friendly icons

Avoid:

- excessive animation
- bouncing elements
- particle effects
- giant animated backgrounds
- long transitions
- visual noise

Animation must never make the app slower.

---

# 17. FARMER-FIRST MOBILE UI

Design for:

- mobile-first use
- outdoor use
- large touch targets
- readable text
- clear labels
- easy one-handed interaction

Test:

```text
320px
360px
375px
390px
414px
768px
```

No horizontal scrolling.

No overlapping text.

No controls hidden behind other controls.

---

# 18. MOBILE NAVIGATION

Recommended bottom navigation:

```text
Home | Fields | Scan | Alerts | AI
```

Keep it limited.

Put secondary pages inside their respective sections.

# 19. SCAN SCREEN

Keep Scan focused:

```text
Scan Crop

Take a clear photo of a leaf,
plant, stem, or fruit.

[ Upload Image ]
```

After capture:

```text

```

Processing:

```text

Validating...
Analyzing...
```

Result:

```text
Crop
Main finding
Risk
Short action
```

Then category buttons.

---

# 20. SCAN ACCURACY MUST REMAIN STRICT

Do not simplify away the existing safety rules.

Keep:

- non-crop rejection
- crop validation
- crop confidence threshold
- disease confidence
- no guessed crop
- no default Tomato
- no default Healthy
- no fake confidence
- no stale previous scan
- invalid scans do not update health/heatmap

# 21. FIELD DETAILS

Fields can contain detailed intelligence:

```text
Field
↓
Crop + Stage
↓
Health
↓
Spatial Health
↓
Risks
↓
Scans
↓
Recommendations
```

Use tabs/accordions when needed.

Do not create a huge vertical wall of cards.

---

# 22. HEATMAP

The heatmap belongs in Fields.

Show a compact preview:

```text
Spatial Health
[ Map Preview ]
[ View Full Map ]
```

Use real field/scan data.

Never use random hotspots or fake health values.

---

# 23. ANALYSIS

Put advanced data here:

- Scan history
- Disease trends
- Pest trends
- Risk trends
- Health history
- Charts
- Detailed statistics
- Scan comparison

This prevents Home and Scan from becoming overloaded.

---

# 24. ALERTS

Home shows only important/current alerts.

Full detail belongs in Alerts:

```text
Alert
Field
Risk
Reason
Date
Recommended action
```

---

# 25. PERFORMANCE

This simplified UI must also improve performance.

Home should fetch only:

```text
User
Weather
Important Alerts
Small Health Summary
```

Do NOT fetch on Home:

- full field dataset
- complete scan history
- full heatmap
- full analytics
- large galleries
- detailed crop history

Use:

- request deduplication
- caching
- parallel requests where appropriate
- lazy loading
- optimized images

---

# 26. LOADING UX

The interface must respond immediately.

Examples:

```text
Scanning...
Analyzing...
Thinking...
Listening...
Loading field...
```

Use skeletons where appropriate.

Never show a blank page while secondary data is loading.

---

# 27. ERROR UX

Use simple messages:

```text
Couldn't save this field.

[ Try Again ]
```

not:

```text
ERR_SUPABASE_POSTGREST_422
```

Errors in one module must not break the rest of the application.

# NON-NEGOTIABLE RULES

1. **Show less, not less functionality.**
2. **Every complex result gets buttons/details instead of one giant screen.**
3. **AI answers remain short by default.**
4. **Home remains minimal.**
5. **Detailed information lives in dedicated pages.**
6. **No fake data.**
7. **No fake AI confidence.**
8. **No default Tomato/Healthy.**
9. **One phase at a time.**
10. **Test → Report → STOP → Wait for approval.**
11. **Do not install/migrate to Capacitor until the web UX/core is approved.**
12. **Edge AI and IoT are the final phase.**
