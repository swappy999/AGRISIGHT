# AgriSight — PHASE-WISE SIH26180 DEVELOPMENT MASTER PLAN
## Build One Phase at a Time • Verify Before Moving Forward

> **CRITICAL INSTRUCTION FOR ANTIGRAVITY**
>
> Do NOT implement all future features at once.
>
> Work **phase by phase**.
>
> Complete one phase, test it thoroughly, fix all issues, and only then move to the next phase.
>
> **Do not start the next phase automatically.**
>
> At the end of each phase, stop and provide a report:
>
> - What was implemented
> - What was fixed
> - What was tested
> - What remains
> - Whether the phase is ready for approval
>
> Wait for explicit approval before beginning the next phase.

---

# GLOBAL RULES FOR EVERY PHASE

## Rule 1 — One Phase Only

Antigravity must only work on the current phase.

Example:

```text
Phase 1
↓
Implement
↓
Test
↓
Fix
↓
Report
↓
STOP
```

Do not jump to Phase 2.

---

## Rule 2 — Preserve Existing Functionality

Before changing anything:

- inspect existing architecture
- inspect routes
- inspect APIs
- inspect database
- inspect state management
- inspect current UI
- inspect existing AI integrations

Do not break working functionality.

---

## Rule 3 — No Fake Features

Never create:

- fake analytics
- random heatmaps
- fake disease alerts
- fake crop predictions
- fake confidence scores
- fake weather data
- fake sensor values in production
- fake AI results

If demo data is genuinely required:

```text
DEMO_MODE=true
```

Keep it isolated from production.

---

## Rule 4 — No Silent Failures

Every feature must clearly communicate:

- loading
- success
- empty state
- error
- retry

Never leave the user with a blank screen.

---

## Rule 5 — Real Data Flow

Use:

```text
Database
→ Backend
→ Structured API
→ Frontend
```

Do not make the frontend invent data.

---

## Rule 6 — Performance

Every phase must avoid unnecessary:

- API calls
- database queries
- AI calls
- rerenders
- polling
- large payloads
- heavy synchronous work

Use caching and lazy loading where appropriate.

---

## Rule 7 — Mobile First

Every phase must work on:

```text
320px
360px
375px
390px
414px
768px
1024px+
```

No horizontal overflow.

No overlapping UI.

---

## Rule 8 — AI Safety

Never guess when confidence is insufficient.

The system must prefer:

```text
UNCERTAIN
```

over a fabricated answer.

# PHASE 1 — WEATHER + ENVIRONMENTAL INTELLIGENCE

## Objective

Turn weather from a simple widget into useful agricultural intelligence.

Do NOT build irrigation, pest prediction, officer dashboard, or Digital Twin yet.

Only build the Weather Intelligence layer.

### Inputs

Use the existing weather provider/API if available.

Collect where available:

- Temperature
- Humidity
- Rain probability
- Rainfall
- Wind
- UV
- Forecast
- Extreme weather indicators

### Build

Create an agricultural interpretation layer:

```text
Weather Data
↓
Environmental Analysis
↓
Heat Risk
Rain Risk
Extreme Weather Risk
```

Example:

```text
🌡️ Heat Risk: HIGH
🌧️ Rain Risk: LOW
☀️ UV Risk: MEDIUM
```

### Requirements

- Current weather
- Forecast
- Agricultural interpretation
- Clear explanations
- No unsupported scientific claims
- Loading/error states
- Caching
- Mobile support

### Home

Only show a small useful weather summary.

Do not turn Home into a weather dashboard.

### Exit Criteria

- Weather loads reliably
- Weather failures do not break Home
- Agricultural risk indicators work
- Data is real
- No duplicate API calls
- Mobile works
- Performance remains good

Then STOP.
